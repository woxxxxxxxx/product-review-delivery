# 逻辑闭环与现状证据

## 先固定事实，再决定改动

为受影响的现状页面登记 E 编号：环境、产品版本/构建号、核验日期、角色、入口路径、动作、观察结果、截图/录屏路径。`production-live`、`uat-live`、`sit-live`、`historical`、`code-only`、`user-provided`、`unknown` 分开记录。只有在目标环境真实操作并留存材料，才可声明该环境实测；正式包模拟器记录设备/包版本，不能写成实体真机。访问失败记录失败位置，不以路由、APK 字符串或假按钮补足“线上页面”。

开始基于现网迭代时按页面重新检查受影响路径。旧证据可以作为历史参考，时间、版本和覆盖范围必须保留；不要根据一个固定天数自动认定证据仍有效。登录、设备或权限不足时继续方案建议和可验证部分，把受阻页标“现状待核实”。只有真实新增的页面才标“新增”，缺截图不等于新增。

现状与改版必须同页、同角色、同状态比较。说明保留、修改、新增各自范围。对照截图不拉伸，后台完整工作区可滚动。接口/代码说明能力线索，页面截图说明呈现，实际操作说明该路径行为；三者不能相互替代。

## 业务契约

逐需求 R 记录：目标、范围、依据、规则、页面 P、状态转移 T、验收 C、决策 D。每个数字边界/完成条件必须有来源或明确为建议；不要用示例数值补规则。声明主体、资源、输入、前置、授权角色、触发、输出、完成标准、副作用、失败恢复。

多步骤任务检查：入口 → 资格 → 填写 → 校验 → 确认 → 提交 → 受理 → 执行 → 结果 → 后续。按场景适用性覆盖下表；不适用写原因，不能一律加与业务无关的分支。

| 类别 | 必问与应有结果 |
|---|---|
| 基础 | 空列表、加载、空值、格式、最小/最大/刚好边界、无权限、登录过期 |
| 导航 | 返回保持输入、刷新恢复、关闭取消、跨页定位、深链进入、重新进入 |
| 事务 | 连点/重试不能重复副作用；提交前与提交瞬间条件变化；两人同时操作 |
| 异步 | 区分反馈与执行事实；简单操作异常可合并失败提示，通过原入口安全重试；防止重复副作用及迟到结果覆盖新状态。不强制新增用户查询页 |
| 组合 | 总状态与子项事实一致；部分成功保留成功项，恢复只重做未完成项 |
| 运营 | 转人工有责任角色、响应时限（未定则决策项）、处理记录和结束结果 |
| 联动 | 名额/余额/权限、通知、历史记录与可追溯性；通知失败不反转已成功业务 |
| 存量 | 旧数据默认值、字段缺失、兼容、迁移、回退/停用后的用户结果 |

多步骤和异步需求用状态表/状态图；跨岗位用泳道；同一维度比较用表格；长营销页保留连续滚动和真实导航，不强改成表单向导。

## 六角色走查与复核

每个视角写具体发现 → 影响 R/P/T/C → 修正或待决策 → 重测证据。没发现也写实际检查范围，禁止空填“通过”。

- 用户：从真实任务开始，不依靠讲解找到入口；失败后知道下一步，返回不会无故丢数据。
- 业务：规则一致，名额/权益/时间/范围正确；例外与分期有依据，新增能力未冒用确认。
- UI/设计：现网层级与组件、同状态对照、信息优先级、窄屏/长文/焦点/键盘/禁用原因完整。
- 研发：前置/后置、来源与去向、并发/异步/重复、恢复、权限和依赖清楚；实现选型不冒充业务定论。
- 测试：每条规则有可判定预期；正向/负向/边界/返回/重试可执行，不是仅查标题/关键词。
- 运营：查询、处理、通知、追踪、人工升级、存量和故障时能落地；不把“联系客服”当闭环。

发现 P0/P1（错误成功、权限越界、数据/权益错误、关键路径断裂、伪造现状）必须修正或保持阻塞，不能打包为就绪稿。修复后复测受影响路径及一条关联回归；多轮直到问题闭环，未能闭环明确原因。

## 可验证的验收

每条 C 包含前置、具体动作、可观察预期、业务结果及类别；原型可执行用事件序列与断言。另记执行版本、日期、结果与证据。测试预期来自已确认规则或明确建议，不因实现恰好如此就视为正确。

联调验收查最终接收端：如线索进 CRM、权限对目标用户可用、名额真实变化。页面 toast、HTTP 200、脚本结构通过都不足以证明业务完成。方案/原型质检与生产验收分开。

## 维护唯一版本

项目入口指向当前原型与 PRD，记录版本、决策、证据、未决项、已跑测试和下一步。更改规则时写影响范围，并同步所有表达同一规则的产物。文件名“最终版”不代表最新；弃用稿不删除，明确归档，入口不再指向它。
