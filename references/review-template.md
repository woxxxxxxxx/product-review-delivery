# 产品评审模板

## 首页

标题：[产品名] [功能范围] 产品方案
版本：[版本]；状态：[待评审/已确认/迭代中]。
用一段话说明用户场景、当前问题和目标。紧接方案建议、范围、评审事项。

## 页面说明

- 页面编号与名称；从哪里进入；适用用户/操作岗位。
- 左：同一页面现状截图或明确标识的结构还原。右：拟上线页面。
- 新增页：现状侧描述旧路径及缺口，不伪造旧页面。
- 变更编号：位置 → 当前表现 → 本期改动 → 用户价值。
- 交互：动作 → 条件 → 页面反馈 → 业务状态 → 下一步。
- 字段：名称 → 必填/选填 → 格式与来源 → 错误提示。未知约束写待确认，不能用测试样例反推生产规则。
- 验收：给定条件 → 操作 → 页面结果与后台结果。

## 状态与责任

状态表列：当前状态、触发事件、下一状态、用户显示、责任方、超时或失败处理。
对外部系统分别标明提交受理与业务完成，说明重复或迟到结果怎样影响用户结果，技术机制由研发评估。

## 分期

阶段、交付范围、依赖、上线门槛、后续扩展。没有估算依据不编造开发人日和发布日期。

## 表达示例

原句：已基于你提供的截图完成优化，并核对了后台。
交付句：本期在车主认证详情增加审核状态和执行结果，客服可据此区分待审核、处理中与已完成。

原句（画布中）：只提交认证，不会生成另一项子单，IMS 不变。
用户界面：标题“确认车主认证”，按钮“提交认证”。
页面外规则：仅提交车主认证申请；车辆绑定由用户单独发起。

原句：测试数据可以通过校验进入下一步。
验收句：必填项完整且通过服务端业务校验后进入确认页；缺少 VIN 时停留表单并提示“请输入车辆VIN码”。
内部验证记录：样例只验证原型必填校验，未验证线上归属与生产 VIN 格式。
