# APP组件与交互决策

适用：消费端APP原型、页面迭代、UI/研发交付。先匹配该产品已核实的组件；以下是用户默认偏好与选型依据，不能覆盖本轮明确要求。

## 控件选择

| 任务 | 默认组件 | 行为约束 |
|---|---|---|
| 两项互斥填写 | 直接单选，短文案可并排，长文案两行 | 整行可点；是否预选取决于业务是否有真实默认值；不可用开关替代两个互斥身份 |
| 三项及以上、数量有限的单选 | 收起式下拉单选 | 标签常驻、显示当前值与展开标识；就地弹出列表或按现有APP采用底部选择层；点选即回填收起，避免多一次确认 |
| 很长或动态单选列表 | 可搜索选择页或选择层 | 保留原值；明确空结果、加载失败与重试；不用长滚轮选无序长文 |
| 多选 | 复选框组或多选选择层 | 明确最少/最多数量；只有需批量暂存时增加确认 |
| 立即生效的布尔设置 | 开关 | 切换反馈成功/失败；失败恢复原值；不冒用开关表达申请审批 |
| 类型不同的业务入口 | 操作行或导航卡片 | 即使只有两项，也不把导航当表单单选；点击直接进入对应任务 |
| 已有身份/车型/账号 | 只读摘要或预填 | 已由可信上下文确定时不重复要求输入；切换上下文重验关联数据 |

“两项直接单选、多项下拉”是本用户的表单偏好，不是苹果/安卓硬性数量规范。保留条件例外：需同时比较关键影响时可展示选项摘要，不因数量机械隐藏必要信息。客户原因用固定选项，“其他”无需自由文本，除非用户另行要求。

## 状态与行为

- 下拉：未选、已选、展开、禁用、错误齐全；选项唯一值与文案分开。取消、点外侧和返回不偷偷修改原选择。重新打开定位已选；键盘可操作、焦点可见、读屏有标签和选中状态。
- 表单：标签常驻，不能只用占位文字。错误靠近字段并告诉用户如何修正，保留已填内容。切换事项只清除不再适用的信息。返回保留草稿，提交形成不可被草稿改写的记录。
- 少操作：同页验证，已选车辆直接带入，不重复确认已完成验证；解绑等有真实后果的操作保留一次清楚确认。自动回填不等于审核或成功。
- 页面：一个明确主动作，次要动作不与主动作同权重。记录/低频管理使用稳定入口；空态引导添加，只有有效关系时出现解除操作。
- 反馈：短操作优先一个加载指示，返回结果自动收起；可重试错误使用简短、不阻断的页内提示，字段错误仍放字段旁。该用户默认偏好导航下方顶部短提示，约3秒后消失，原操作按钮可重试；这是项目偏好，不是iOS/Android统一强制规范。错误不能只靠颜色表达，读屏可播报，提示不遮返回/安全区/主动作。严重后果或需用户决策才用弹窗。
- 简化：默认复用原按钮重试，不为每种网络异常新增状态页、确认或查询入口。简单操作的超时可归入失败反馈，但实际执行结果不能被客户端改写；重试依赖既有防重或当前状态校验，已成功不得重复执行/通知。只有风险或长任务确实需要时才向用户展示独立查询流程。演示控制放画布外。
- 视觉：沿用现网品牌色、导航和组件；建议APP正文16px、次要文字13–14px，触控行至少48px并检查真实设备。用4/8间距节奏，不照搬B端密集字段表。安全区、键盘遮挡、长文、字号放大需验收。
- 原型表现：桌面浏览器默认下拉/文件按钮不代表原生APP设计；高保真稿需体现目标端选择层和上传区。保留语义和键盘可用性，禁止只有画面无反馈。

## 业务对象辨别

出现相似名称、手机号或多端账号时，先分别列清：账号身份、登录凭证、终端登录态、车辆绑定/授权、认证及历史记录。不能因为同一字段显示不同就创建一个“更改业务号码”功能；也不能因为扫码登录就推导强制退出或自动授权。产品约定用户结果与安全边界，研发核实跨端能力。项目事实留项目入口，不将单一品牌规则写成通用规范。

## 交付检查

逐表单记录：字段用途→选项数量→控件→默认值→触发→校验→返回/取消→提交结果；至少实际点击未选、选择、切换、返回与提交一条路径。检查默认折叠的内容是否可发现。规则与原型、消息、PRD、验收一致。

## 参考与采用边界

查阅日期：2026-10-14。
- [Apple Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers)：按列表长度与使用情境选择，不为短列表增加笨重滚轮。
- [Android Menus](https://developer.android.com/develop/ui/compose/components/menu)：输入字段可作为下拉锚点，列表按需展开。
- [Android Radio button](https://developer.android.com/develop/ui/compose/components/radio-button)：互斥选择与可点击选项行。
- [Expo官方UI skill](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-ui/SKILL.md)：有原生选择、菜单、表单组件映射；仅Expo实现采用对应技术选型，不强制HTML或其他APP重构框架。
- [mobile-app-ui-design](https://github.com/ceorkm/mobile-app-ui-design/blob/main/SKILL.md)：参考状态完整与层级原则；不采用无条件情绪动画、过大留白、其他选项强制手填等与本项目冲突的条目。

仅提炼可复用决策，没有安装第三方脚本或修改项目技术栈。

反馈依据（2026-10-14）：[Apple Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback) 强调反馈与打断程度匹配；[Android Snackbar](https://developer.android.com/develop/ui/views/notifications/snackbar) 采用短暂、非阻断提示且常在底部。因此顶部短提示作为本项目选择，不能宣传为跨平台强制标准。
