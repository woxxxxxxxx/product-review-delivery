# 可复用 HTML 评审模板

复制 `assets/review-kit/` 到项目内新目录即可双击 `index.html`，无构建、无 CDN、无需后端。先复用已有最新交付目录，不覆盖仍需留存的版本。模板是通用“申请办理”的虚构演示，不能当真实业务规则或现网证据。

- `index.html`、`styles.css`、`workbench.css`：6.1 评审外壳与语义颜色，默认业务视角的页面预览，全部信息可显式展开。
- `data.js`：单一契约（纯 JSON 包在 `window.PRODUCT_REVIEW = …;` 中），驱动可见规则、状态、验收与证据表。
- `app.js`：示例业务交互和审阅导航。换项目时必须替换业务画布/校验/动作；不能只改数据标题。
- `workbench.js`：APP/H5/PC 示例适配、页面矩阵、角色流程、需求覆盖与场景预览；这些映射须按具体项目替换，不自动推断真实端能力。
- `editor.js`：显式保存的本地文案/样式编辑、撤销重做、JSON 导入导出和独立 HTML 导出。
- `flow.js`、`flow.css`：入口/响应条件联动、可点击状态图、跨端交互时序、字段去向与本次操作轨迹。具体业务节点和字段须随项目契约一起修改，不由状态表自动生成整张图。
- `audience.js`、`audience.css`：六种角色信息筛选（业务含运营职责）、当前页关注点、规则锚点及组件编辑视觉。角色不是权限，不变更业务记录；打印按所选角色筛选章节。
- `presentation.js`：浏览器编辑器与交接读取脚本共用的展示层校验，限制文案、基础样式和同页组件完整排序；拒绝未知样式、重复/缺失组件和版本冲突。
- `bundle.js`：导出所需的原始模板资源，由 `node scripts/build_review_bundle.cjs [单文件输出路径]` 生成。每次改 HTML/CSS/JS 后必须重建，否则导出仍是旧代码。生成的单文件可离线打开，不需要源目录。
- `python scripts/check_contract.py <data.js>`：检查结构，退出 0 不代表人工评审通过；`--gate ready` 检查适用验收已执行及角色走查记录。核验程序不会访问现网，也不能判断截图是否真实，需操作者看证据。

## 固定布局，按需展开

打开默认直接看方案。左侧为内容目录；上方切换方案、现状对照、业务后台；右侧仅显示当前页的简短改动，并可收起。需求目标、范围与规则放“需求说明”，不做开场大卡片。演示条件默认展开，缺证据的现状仅在对照模式明确显示占位，不能因默认隐藏现状就标为已核实。

演示条件按 1 入口 → 2 页面操作 → 3 模拟查询返回排列。入口切换清除本轮输入/轨迹并退出场景预览；未提交、无事项、无权限、帮助页、已结束时禁用响应选择并说明下一步。提交后选择查询返回立即执行一次模拟查询；同一结果可以重复选，反馈查询次数。画布“查询结果”默认模拟未知，画布外明确说明；不依赖隐藏预设。编辑模式暂停入口、查询返回和重置，结束编辑按真实状态恢复可用性。

对照时两侧保持相同视口宽度，窄屏顺序堆叠；后台用全宽独立视图，不挤进手机。屏外设置演示条件，业务按钮按真实操作触发状态；禁止把“成功/失败”测试按钮放进用户页面。导航只改变查看内容，不提交或重置业务状态。切换章节、刷新与浏览器返回应可用；打印输出各章节而非仅打印当前标签页，并恢复打印前视图。

视觉采用白/中性灰底，按含义使用蓝色主路径、绿色完成、琥珀色待确认/结果未知、红色明确失败、紫色编辑草稿；每个颜色搭配文字。端标识与状态标识分组展示。不要添加营销横幅、口号、大面积渐变、英文装饰分区或无意义指标卡。通用示例的服务中心只是样例，不构成新项目视觉规范。

## 多端与多维度

原型工具栏选择 APP、H5端、PC 后台；右侧按当前页切换改动、规则、验收。APP 与 H5 仅在这个示例共用申请流程，外观和文案编辑独立；PC 仅查询记录，提交前显示空态，不假造运营审核能力。

多端全景按目的切换：端×任务阶段矩阵帮助定位页面；角色流程用时序图展示谁发起、谁响应、传递什么；端间数据展示字段产生方、流转时机、用户端/服务/后台当前值和本次轨迹；需求覆盖关联 R/P/C。点击全景格子或状态图节点打开明确标识的“场景预览”，不触发真实请求，也不覆盖原操作草稿；退出恢复原状态。换项目时仅显示适用端和有证据/明确建议的能力，不为“全量”编造移动端或后台。

草稿和已受理事项分别保存；提交前后台无记录，失败返回修改时后台仍显示上次提交值和失败结果，重新提交才更新。后台执行状态不能跟着用户的“填写/核对/帮助”页面状态变化。时序图是业务关系示意，不是调用日志；本次轨迹只记录实际发生的本地状态动作，场景预览不补造前序事件。APP/H5 切换仅用于评审同一任务，不承诺跨设备草稿同步。

状态图主干、分支、返回线和条件文字清楚分层。长图窄屏可横向滚动，不能将标签缩成不可读；节点支持鼠标和键盘预览。完整状态转移表保留，图只摘要时明确说明。

## 画布编辑与保存

开启“编辑画布”后直接点击静态文字或按钮输入，也可在右侧调整文字颜色、背景色、字号和对齐。输入值、动态业务结果、状态规则不是编辑目标；编辑时暂停业务按钮动作。结束编辑后恢复交互，提交前禁用条件仍须成立。

每个编辑目标使用“端 / 状态 / 元素”稳定标识。项目改布局时同步编辑目标与验证，避免按 DOM 顺序错误套用。编辑只产生展示层覆盖，不改 PRD/动作/权限。修改版显示“逻辑待复核”，不得以换了按钮文案宣称功能完成。

6.1 支持拖动画布组件右上角手柄排序，也支持键盘上下键及属性栏上移/下移。只调整当前端、当前状态的完整组件组；DOM 顺序和视觉顺序同步，不用任意坐标/遮挡方式摆放。输入框、标签、错误提示不可拆分；PC 表格不开放重排列。排序纳入撤销、重做、恢复、保存和导出。布局变更必须复查按钮可发现性、阅读顺序、键盘顺序、窄屏与原业务路径。

切换“规则”后，当前页全部适用规则都映射到业务画布：元素旁编号、悬停原元素或编号显示就地说明；支持键盘聚焦、点击固定、Escape收起。规则文本引用同一契约，不手写两套。侧栏保留目录与定位，不能只列侧栏而画布无标注。未出现的条件控件将说明锚定当前页相关区域，标明适用条件；不能伪装为已有控件，也不拿其他页面规则凑数。滚动、缩放、端/状态切换后重新定位，离屏目标不显示漂浮编号。进入编辑、普通改动视图或打印时隐藏；悬停不触发业务操作，提示可移入阅读、不遮主动作。复用 `rule-annotations.js` 引擎，不只参考文字规范。

模板示例的完整异步分支只是能力演示，不是项目必选流程。按最小闭环裁剪，简单操作默认加载→成功/失败反馈→原入口重试；仅在实际风险需要时保留独立未知查询页。

评审角色和查看端是两个维度；默认业务视角合并运营职责，保留需求范围、待确认事项、端与页面、角色流程和 PC 办理记录，隐藏较深实现章节及端间数据、需求覆盖；可一键显示全部。屏幕与打印使用同一筛选范围，切换角色不切换业务端或重置状态。角色关注点、规则锚点和端覆盖须按项目实际规则定制，示例不能冒充现网。

- 保存草稿：显式写入当前浏览器、当前模板版本；刷新恢复，未保存关闭给浏览器提示。存储失败保留内存改动并显示失败。跨浏览器、文件路径或设备不保证共享。
- 撤销/重做：当前会话保留最多 80 步；刷新后恢复最后保存稿，不保留撤销历史。
- 导出修改：可迁移 JSON，只接受相同项目/模板版本、白名单目标、纯文字和限定样式；不解析文字中的 HTML 或执行脚本，并拒绝任意 CSS、超大文件或不匹配版本。导入替换需确认且可撤销。
- 导出 HTML：将修改和运行资源保存成独立文件，打开即显示修改，也能继续编辑；不附带演示输入和业务草稿。新导出文件有独立本地存储标识。
- 导出交接包：包含基础版本/资源指纹、稳定目标和文案/样式/顺序修改，可附修改目的。收到文件后按 [presentation-handoff.md](presentation-handoff.md) 读取和复核，禁止把本地保存描述成已自动上传或合并。
- 保存和导出均不自动回写本地源文件、线上系统、Figma 或其他协作者；修改文件需带回项目核对后再纳入正式源。

必测：文字编辑、样式修改、撤销重做、刷新恢复、端/状态隔离、禁用业务按钮恢复、空文案阻断、存储失败、非法导入、独立 HTML 无源文件打开与再次导出。不要只测试编辑框出现。

流转必测：提交前响应禁用、空/权限入口立即生效、提交后选择即时更新、未知重复查询有反馈且不重复提交、帮助返回、失败修改保留已提交快照、重新提交刷新后台、完成/入口重置清理旧结果、场景退出恢复草稿、编辑模式禁用模拟条件、跳端不变更记录、图中节点/方向与实际恢复行为一致。

例子包含输入、核对、受理、处理中、未知、失败、完成、空、无权限与人工帮助；刷新恢复本地示例输入，清理只清理当前模板数据。项目如不使用浏览器持久化，可改为明确提示刷新重置。模型中的 T 必须和实际按钮、界面状态一致。

每个已有页面的 `baseline` 可为 `unknown`、`historical`、`verified`。`verified` 要关联与目标环境匹配的实测证据、当前轮复核标记、截图和观察记录。`new` 页写明旧任务如何完成与新增原因。无证据时显示占位说明，绝不默认画一张“现状”。

## data.js 约定

`meta` 定义项目、版本、目标环境、阶段；`requirements` 记录 R；`pages` 记录 P/R/证据；`states` 定义状态及终态；`transitions` 记录 T 的起止/事件/条件/可观察效果；`cases` 用 `path` 指向 T，含 `given`/`expected`/`result`/`run_evidence`。`coverage` 对基础类别填 `required` 或带原因的 `na`；新增业务类别也可添加。`decisions`、`reviews`、`artifacts` 保存未决项、角色走查和产物。

检查阶段不允许断引用、重复 ID、不可达状态或无出口非终态；就绪阶段要求适用类别有已执行通过用例、六角色有检查范围及证据、阻断决策已解决。手工结果不能让程序自动填“通过”；使用真实执行记录补齐。

## 实际交互与视觉验收

用浏览器操作每条关键路径及适用异常，覆盖输入→返回修改→确认→重复操作→等待/未知→恢复。观察界面与业务状态是否一致，DOM 检查不能代替点击。按目标设备宽度（示例 1440/1280/390）检查外层溢出、表格滚动、长文、按钮、焦点及打印。保存截图并实际查看；记录没有测到的范围。

原型演示的网络失败/成功是模拟，不宣称真实服务已验证。对外只交付入口和所需源文件，质检记录、脚本、原始证据留工作区。自动化测试只操作本地演示，不擅自提交生产数据。

- [NN/g Task Scenarios](https://www.nngroup.com/articles/task-scenarios-usability-testing/)：以真实任务目标测试，避免预先告诉受测者操作答案。
- [Linear 2026 界面更新](https://linear.app/now/behind-the-latest-design-refresh)：导航退后、主内容突出、操作位置稳定，借鉴工具界面的信息密度与视觉层级。
- [GitHub Primer 渐进披露](https://primer.style/product/ui-patterns/progressive-disclosure/)：按需显示次要信息，但关键动作与上下文保持可见。
- [GitHub Primer 保存](https://primer.style/product/ui-patterns/saving/)：保存模式明确、失败保留输入，风险操作提供恢复。
- [Figma 多流程原型](https://help.figma.com/hc/en-us/articles/360039823894-Create-and-manage-prototype-flows)：以任务流程组织入口，而不是把所有画面塞入单一演示路径；本模板未调用或接入 Figma。
- [IBM Carbon 标签](https://www.carbondesignsystem.com/building-blocks/core/components/tag/specifications)：以配套的文字、底色和边框区分标签，颜色用于分类而非纯装饰。
